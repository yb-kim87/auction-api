# 대출 정책 · 물건 추천 로직 요약

추천물건 화면(홈 `/`, 검색 `/search`)에서 "최소 투자금"·"예상 대출금액"을
계산하는 전체 로직 정리. 관련 코드:

- 백엔드: `src/recommendation/investment-math.util.ts`,
  `src/recommendation/recommendation-engine.service.ts`,
  `src/loan-policy/*`
- 프론트: `src/lib/investment-criteria.ts` (검색 페이지 클라이언트 계산),
  `src/app/page.tsx`, `src/app/search/page.tsx`

## 1. 대출한도 계산식

물건 하나에 적용되는 **최종 대출한도**는 아래 세 기준 중 **가장 낮은 값**이다.

```
대출한도 = min(
  낙찰가(최저가) × 정책의 낙찰가비율(loanRatio),
  감정가         × 정책의 감정가비율(appraisalRatio),
  연소득         × 소득배수(incomeLoanMultiplier, 기본 7배)
)
```

- 소득 정보가 없으면(회원정보 미입력) 소득 기준은 적용하지 않는다(무제한 취급).
- 소득 **0원**은 "정보 없음"이 아니라 유효한 입력이다 → 소득 기준 한도가 0으로
  잡혀 사실상 대출 불가가 된다. (`parseIncomeToWon` 참고, 아래 5번 항목)

그 다음 **기존대출을 차감**해서 실제 신규 대출 가능액을 구한다.

```
실제 대출가능액 = max(0, 대출한도 - 기존대출금액)

필요 자기자금(최소 투자금) = 낙찰가(최저가) - 실제 대출가능액
```

구현 함수: `requiredEquityForItem(minPrice, appraisedValue, policy, annualIncomeWon, existingLoanWon, incomeLoanMultiplier)`

## 2. 적용 정책 선택 규칙

물건의 **규제지역 여부** × 회원의 **주택수·생애최초 여부**로 5가지 정책 중 하나를 고른다.

| 규제지역 | 주택수 | 정책 id | 낙찰가비율(기본) | 감정가비율(기본) | 비고 |
|---|---|---|---|---|---|
| O | 0주택(생애최초 포함) | `regulated_no_house` | (사실상 무제한, 관리자가 실제값 입력 가능) | 40% | 무주택자만 가능 |
| O | 1주택 이상 | `regulated_owner` | 0% | 0% | **대출 불가** |
| X | 0주택 + 생애최초 | `unregulated_first_time` | 90% | 90% | |
| X | 0주택(생애최초 아님) | `unregulated_no_house` | 80% | 70% | |
| X | 1주택 이상 | `unregulated_owner` | 70% | 70% | 사업자대출만, 단타만 가능 |

- 규제지역 판정: 관리자가 "규제지역 목록"(시/도, 구/군, 읍/면/동 단위)을 등록해두면,
  물건 주소(`city`/`district`)에 그 지역명이 포함되는지로 판정한다.
  (`isRegulatedArea`, `RegulatedRegionService`)
- **중요**: 규제지역 정책의 "낙찰가비율" 기본값은 사실상 무제한(더미값)으로
  세팅되어 있지만, **관리자가 대출정책 관리 화면에서 실제 의미 있는 값(예: 80%)으로
  직접 수정할 수 있다.** 이 경우 감정가비율(40%)과 낙찰가비율(80%) 중 더
  낮은 쪽(감정가 40%)이 실제로 적용된다 — 두 값 다 유효한 상한이고,
  최종적으로 min()이 선택한다.

선택 로직: `selectLoanPolicy(criteria, regulatedArea, policies)`

## 3. 관리자가 조정 가능한 값

**대출 정책 관리** 화면(관리자 > 대출 정책 관리)에서:

- 정책별 낙찰가비율(%) / 감정가비율(%) — `regulated_owner`(대출불가)만 수정 불가
- 소득 대비 대출 배수(기본 7배) — 전역 설정 하나
- 규제지역 목록(시/도, 구/군, 읍/면/동 다중 선택 가능)

## 4. 화면에 보이는 대출 비율 표시 (중요 — 과거 버그 수정됨)

**정책의 raw `loanRatio`(낙찰가비율)를 그대로 "대출 OO%"로 보여주면 안 된다.**
감정가비율이나 소득 기준이 더 낮게 걸려 실제로는 그 비율이 적용 안 됐을 수
있기 때문이다. 예: 규제지역 정책의 낙찰가비율을 80%로 설정해도, 감정가비율
40%가 더 낮으면 실제로는 40%가 적용되는데, 화면에 80%라고 잘못 표시되던
버그가 있었다(2026-07-14 수정).

**올바른 표시 방법**: 실제 결과값에서 역산한다.

```
실제 적용 비율 = (최저가 - 필요자기자금) / 최저가
             = (minPrice - requiredEquity) / minPrice
```

`src/app/page.tsx`의 `RecommendCard`/`RecommendListRow`가 이 방식으로 계산한다.

## 5. 신용점수 처리

- 신용점수 750점 미만이면 물건 추천 목록은 그대로 보여주되, 화면 상단에
  경고 배너("신용점수 확인 필요")를 띄운다. 추천 결과 자체를 걸러내지는 않는다.
- 판정 함수: `needsCreditScoreWarning(creditScore)` — 회원정보의 신용점수
  문자열("750~799점", "900점 이상", "350점 미만" 등)에서 하한값을 파싱해 750
  미만인지 확인.

## 6. 소득 0원 관련 주의사항 (과거 버그, 수정됨)

`parseMoneyToWon`(투자가능자금 등 범용 금액 파서)은 "0"을 무의미한 값으로
보고 `null`을 반환한다. 이 함수를 그대로 연소득 파싱에 쓰면 "소득 0원(소득없음)"과
"소득 정보 미입력"이 똑같이 취급되어, 소득 기준이 전혀 적용되지 않는 버그가
있었다(2026-07-14 수정). 소득 전용 파서 `parseIncomeToWon`을 사용해 "0"을
유효한 입력으로 인정하도록 고쳤다.

## 7. 규제지역 배지 표시

홈 화면(`/`)의 추천물건 카드에는 물건별로 "규제지역"(빨강) / "비규제지역"(초록)
배지를 표시한다. 판정값은 백엔드가 계산한 `loanInfoByItemId[id].regulatedArea`
(`isRegulatedArea` 결과)를 그대로 사용한다 — 프론트에서 다시 판정하지 않는다.

## 8. 프론트 계산 로직 중복 주의

홈 화면(`/`)은 **서버(백엔드)가 계산**해서 `loanInfoByItemId`로 내려주고,
검색 페이지(`/search`)는 **클라이언트(`investment-criteria.ts`)가 동일 로직을
따로 구현**해서 계산한다. 계산식을 수정할 때는 양쪽(`investment-math.util.ts`
와 `investment-criteria.ts`)을 함께 고쳐야 한다.
