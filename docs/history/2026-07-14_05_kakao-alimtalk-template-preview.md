# 카카오 알림톡 템플릿 미리보기 변수 표시 버그 수정

날짜: 2026-07-14
관련 레포: auction

## 배경

관리자 콘솔의 "알림톡 템플릿 설정" 화면에서 템플릿을 선택하면 변수 입력창은
정상적으로 나타나지만(#회원명, #날짜 등), 미리보기 영역에는 첫 번째 변수(#회원명)만
보이고 두 번째 이후 변수(#날짜)는 안 보이는 문제가 보고됨.

## 실행 프롬프트 (요약)

```
알림톡 템플릿 설정에서 빨간네모박스에 원래 두번째 변수(#날짜)가 들어가야하는데
안나오는거 같아 확인하고 나오게 해줘 첫번째 변수만 나오네
```

## 원인

`KakaoNotifyPanel.tsx`의 템플릿 미리보기 렌더링(`AlimtalkPreview`에 넘기는 `content`)에서,
아직 값을 입력하지 않은 변수는 `varValues`에 빈 문자열(`""`)로 저장되어 있음.
`renderTemplateContent`는 변수 키가 존재하면(`hasOwnProperty`) 그 값(빈 문자열 포함)으로
치환하므로, 빈 문자열이 그대로 치환되어 미리보기에서 텍스트가 사라진 것처럼 보임.

- 첫 번째 변수("회원명"/"이름" 포함)는 템플릿 선택 시 자동으로 리드의 "이름" 필드
  참조(`$field:name`)로 채워지기 때문에 우연히 값이 있어 정상 표시됨.
- 두 번째 이후 변수는 관리자가 직접 값을 입력하거나 필드를 선택하기 전까지는
  빈 문자열 상태라 미리보기에서 빈칸으로 사라져 "변수가 안 나온다"고 느껴짐.

## 변경 내용

- `src/app/admin/KakaoNotifyPanel.tsx`: 템플릿 미리보기용 변수 매핑에서, 값이 비어있으면
  실제 렌더링 결과에 원래 자리표시자 `#{변수명}` 형태를 그대로 보여주도록 수정
  (`v || \`#{${k}}\``). 필드 참조(`$field:xxx`)가 선택된 경우는 기존처럼 `{필드라벨}`로 표시.

## 결과
- 값을 아직 입력하지 않은 변수는 미리보기에서 `#{날짜}`처럼 원래 표기 그대로 보여
  "어떤 변수가 아직 비어있는지"를 관리자가 바로 확인할 수 있게 됨
- 발송 이력 상세의 미리보기(별도 컴포넌트, 이미 저장된 실제 값을 보여주는 화면)는
  이번 버그와 무관해 변경하지 않음

## 추가: 카톡방 클릭 추적이 전부 "클릭 안 함"으로 나오는 문제 (2026-07-15 追記)

### 배경
관리자 화면(알림톡 관리)의 리드 상세보기에서 "카톡방 버튼 클릭"이 실제로 클릭한
리드들도 전부 "클릭 안 함"으로 표시됨. `docs/imweb-landing-tracking.md`의 3번
스크립트(카톡방 버튼 클릭 감지)를 이미 가입완료 페이지에 심어둔 상태였음.

### 진단 과정
1. 백엔드 매칭 로직(`recordKakaoRoomClick`, `matchLeadToVisit`)을 먼저 의심했으나
   코드 자체는 정상
2. 브라우저 Network 탭(Preserve log 켜고 `kakao-room-click` 필터)으로 확인한 결과,
   버튼 클릭 시 해당 요청이 **아예 발생하지 않음**을 확인 — 백엔드가 아니라 프론트
   (아임웹 페이지) 스크립트의 클릭 감지 실패로 범위를 좁힘
3. 카톡방 버튼을 Inspect로 열어보니 실제 `href`가 `https://open.kakao.com/...`이
   아니라 **`https://bit.ly/couchEnd`**(단축 URL)이었음

### 원인
스크립트의 `KAKAO_ROOM_URL_PART = "open.kakao.com"` 조건이 버튼의 실제 href(단축
URL)와 전혀 매칭되지 않아, 클릭 이벤트 리스너의 `if (...indexOf(...) === -1) return;`에
매번 걸려 요청 자체가 발사되지 않았음. 아임웹이 카톡방 링크를 bit.ly로 감싸둔 것을
가이드 작성 시점엔 감안하지 못했음.

### 변경 내용
- `docs/imweb-landing-tracking.md`: `KAKAO_ROOM_URL_PART` 설정 가이드에 "실제 href가
  단축 URL(bit.ly 등)일 수 있으니 반드시 Inspect로 확인하라"는 경고 추가
- 사용자가 실제 아임웹 스크립트의 `KAKAO_ROOM_URL_PART` 값을 `"open.kakao.com"` →
  `"bit.ly/couchEnd"`로 직접 수정해 재배포(아임웹 쪽 변경이라 이 레포에는 코드 변경 없음,
  가이드 문서만 갱신)

### 결과
- 카톡방 버튼 클릭 시 `kakao-room-click` 요청이 정상 발사되는 것을 Network 탭에서
  `201 Created`로 확인
- 향후 유사한 외부 링크 기반 추적 스크립트를 추가할 때는 반드시 실제 DOM의 href를
  먼저 확인하고 조건을 설정해야 한다는 교훈

## 추가: 기존 회원 재클릭이 리드에 반영되지 않던 문제 (2026-07-15 追記)

### 배경
위 수정으로 요청 자체는 성공(`201 Created`)했지만, 실제 리드 상세보기에는 여전히
"클릭 안 함"으로 표시됨. 원인 조사 결과 이 리드가 4일 전(수집시각 7.11)에 이미
생성된 기존 리드였고, 오늘(7.15) 랜딩페이지부터 새로 접속해 테스트하며 발급받은
`visitId`는 이 리드와 연결되어 있지 않았음.

### 원인
`recordKakaoRoomClick`이 `lead.visitId === visit.visitId`로만 리드를 찾았는데,
`matchLeadToVisit`(유입 정보 매칭)은 **리드가 신규 생성될 때 한 번만** 호출되므로,
이미 존재하는 리드는 새로운 방문(visitId)과 절대 연결되지 않는 구조였다. 즉 신규
가입자의 최초 클릭은 반영되지만, **기존 회원이 재방문해서 다시 클릭하는 경우**는
구조적으로 반영될 수 없었다.

### 실행 프롬프트 (요약)
```
기존 유저가 들어오더라도 다시 들어왔을때 카톡을 클릭하면 남길 수 있는 방법이
없을까?? 클릭 시간을 남기면 되지 않을까?? (두번클릭하면 이력으로 남기고)
```

### 변경 내용
- `KakaoLead`/`KakaoLandingVisit`에 `firstKakaoRoomClickedAt`(최초 클릭, 1회만 기록),
  `kakaoRoomClickCount`(누적 클릭 횟수) 추가. 기존 `kakaoRoomClickedAt`은 "가장 최근
  클릭 시각"으로 의미를 확장(재클릭마다 갱신)
- `recordKakaoRoomClick`: (1) visitId로 이미 매칭된 리드가 있으면 바로 갱신 (2) 없으면
  이 방문의 `signupConfirmedAt`과 가장 가까운 `joinedAt`을 가진 기존 리드를 30분
  윈도우로 찾아 **클릭 정보만** 반영(유입 경로 정보는 원래 리드의 것을 그대로 유지,
  덮어쓰지 않음)
- 마이그레이션 `1752960000000-AddKakaoRoomClickCount`: 새 컬럼 추가, 기존
  `kakaoRoomClickedAt`이 있던 행은 `kakaoRoomClickCount=1`로 백필
- 관리자 화면(`KakaoNotifyPanel.tsx`): 2회 이상 클릭 시 "최근시각 (총 N회, 최초
  시각)" 형태로 표시

### 결과
- 신규 가입자의 최초 클릭뿐 아니라, 이미 가입한 회원이 카톡방 링크를 다시 눌러도
  클릭 이력(횟수·최초·최근 시각)이 리드에 정확히 누적됨

## 추가: 회원명 변수를 바꿔도 무조건 이름으로만 발송되던 버그 (2026-07-15 追記)

### 배경
관리자 화면에서 "회원명"(첫 번째, "이름" 포함 변수) 선택란을 다른 필드나 직접입력
값으로 바꿔도, 실제 발송되는 알림톡에는 항상 리드의 실제 이름이 들어감.

### 실행 프롬프트 (요약)
```
알림톡 보낼때 변수 부분에 내용을 보낼때 처음 회원명은 이름으로 자동세팅 되자나
근데 다른걸로 바꾸거나 직접입력으로 바꿔도 무조건 이름으로 보내지는데 이거 한번
확인해서 수정해줘
```

### 원인
`kakao-notify-setting.service.ts`의 `resolveVariablesFor()`가 관리자가 설정한
변수값들을 모두 치환한 뒤, 마지막에 `return { ...resolved, [nameVar]: lead.name
|| "고객" }`로 **항상 nameVar를 리드 이름으로 덮어쓰고** 있었다(원래 주석에도
"이름 변수는 항상 리드의 실제 이름으로 강제 대체된다"고 의도적으로 적혀 있었음).
UI는 회원명 변수를 자유롭게 바꿀 수 있는 것처럼 보이지만, 백엔드가 그 설정을
완전히 무시하는 UI-동작 불일치 버그였음.

### 변경 내용
- `resolveVariablesFor`: 무조건 덮어쓰던 로직을 제거. 이제 nameVar도 다른 변수와
  동일하게 관리자가 설정한 값(필드 참조 `$field:xxx` 또는 고정값)을 그대로 따름.
  `variables`에 nameVar 키가 아예 없는 예외적 경우에만 안전하게 리드 이름으로 채움
- `KakaoNotifyPanel.tsx`: "회원명은 항상 실제 이름으로 자동 대체된다"던 안내 문구를
  "기본은 이름이지만 다른 필드/직접입력으로 바꿀 수 있다"로 수정

### 결과
- 회원명 변수를 다른 필드나 고정 문구로 바꾸면 그 설정이 실제 발송에 정확히 반영됨
- 기본값(신규 템플릿 선택 시 자동으로 `$field:name`)은 그대로 유지되어, 별도로
  바꾸지 않으면 기존과 동일하게 이름이 발송됨
