# 규제지역 주소 파싱 버그 수정

날짜: 2026-07-14
관련 레포: auction-api

## 배경

"용인시 기흥구를 규제지역으로 지정했는데 왜 비규제로 나오는가"라는 제보로 조사한 결과,
주소를 city/district로 분리하는 파서(`address-parser.ts`)에 두 가지 버그가 있었음.

## 실행 프롬프트 (요약, 시간순)

```
(강서구 다세대주택 스크린샷) 이 물건은 왜 대출 50%로 나올까? / 서울 강서구 등촌동...
그리고 용인시 기흥구는 내가 규제지역으로 지정했는데 왜 비규제로 나와?
백필 api를 어떻게 호출해?
(백필 실행 결과 스크린샷) 된거야?
(용인시 기흥구 3개 카드 스크린샷) 같은 기흥구인데 고매동은 비규제라고 나오네??
용인시 기흥구를 포함하고 있으면 규제지역으로 나오게 해야지
아 그런 예외 사항도 적용시켜줘 (경기 vs 경기도 축약형 문제)
```

## 원인

1. **시+구 파싱 누락**: 정규식 `/^(\S+?(?:시|군|구))/`이 "시" 또는 "구" 중 첫 토큰만 잡아,
   "용인시 기흥구"가 `district`에 "용인시"까지만 저장되고 "기흥구"가 잘림. 관리자가
   "용인시 기흥구"로 등록해도 `district.includes(등록명)` 매칭이 실패.
2. **시도 축약형 미인식**: 일부 물건 주소가 "경기도" 대신 "경기"로 시작해 `SIDO_NAMES` 목록의
   어떤 항목과도 매칭되지 않아 `city`/`district`가 아예 빈 문자열로 저장됨(예: "경기 용인시
   기흥구 고매동..." → city/district 공백 → 항상 비규제 판정).

## 변경 내용

- `src/auctions/address-parser.ts`
  - `parseDistrict()`: "일반시+구"(예: "용인시 기흥구", "고양시 일산서구") 패턴을 온전히
    district에 저장하도록 정규식 확장
  - `SIDO_SHORT_NAMES` 추가: 정식 시도명("경기도" 등) 매칭 실패 시 축약형("경기" 등)으로
    재시도. "경기도"의 "경기"만 우연히 겹치는 경우를 피하기 위해 뒤따르는 문자를 검사
- `src/auctions/auctions.service.ts`, `src/auctions/auctions.controller.ts`
  - 관리자 전용 백필 API `POST /api/auctions/backfill-city-district` 추가: 기존 물건의
    city/district를 address 기준으로 재계산해 저장

## 백필 실행 방법 (참고)

관리자 계정으로 로그인된 브라우저 콘솔에서:

```js
fetch("/api/auctions/backfill-city-district", {
  method: "POST",
  credentials: "include",
}).then(r => r.json()).then(console.log);
```

- 1차 배포(시+구 파싱 수정) 후 실행: `{total: 520, updated: 73, unchanged: 447}`
- 2차 배포(축약형 시도명 인식) 후 재실행 필요 — "경기" 축약형 주소를 가진 물건 추가 반영
