# 운영 물건 권리분석 정확도 점검 및 안전장치 보강

날짜: 2026-07-28  
관련 레포: auction-api

## 점검 범위

- 운영 승인 물건 4,007건과 활성 `권리분석` RAG 지식 13건 확인
- 등기·임차·특이사항 원문이 충분한 대표 후보 8건 선별
- 다수 임차인, 선순위 임차권, 보증기관 채권 승계·잔존채권 포기,
  지분매각 유형 포함

## 확인된 문제

- RAG 키워드에 말소기준, 압류·가압류, 임차권, 선순위, 인수금액,
  청구금액, HUG 관련 표현이 없어 핵심 지식이 검색에서 빠질 수 있었음.
- 지식 중요도 등급이 검색 점수에 반영되지 않았음.
- AI가 등기 원문의 `(말소기준등기)` 표시를 놓치거나 청구·채권금액을
  인수금액으로 사용해도 서버 검증이 없었음.
- 저장된 `citations`는 검색된 지식 목록일 뿐 실제 적용 근거를
  확인할 수 없었음.

## 변경 내용

- 원문에서 명시된 말소기준등기 종류·일자, 청구·채권금액, 말소기준일
  이전 전입일, 잔존 임차보증금반환채권 포기 문구를 기계적으로 추출.
- 추출 사실과 주의사항을 AI 프롬프트에 별도 제공.
- 명시된 말소기준등기는 AI 응답보다 원문 추출값을 우선 적용.
- 청구·채권금액만을 근거로 인수금액을 산정한 응답은 서버에서
  `미확인`으로 되돌리고 배당·잔존채무 자료를 요구.
- `knowledgeEvidence`에 실제 적용한 RAG 제목과 적용 규칙을 저장하고,
  검색되지 않은 지식을 근거로 작성한 항목은 제거.
- RAG 검색 키워드 확대 및 지식 등급 가중치 적용.
- RAG 지식 변경만으로 기존 분석을 자동 만료하지 않고 관리자
  `refresh=true` 요청 때만 재분석하도록 기존 운영 방침과 일치시킴.

## 검증

- `npm run test:rights` 통과
- 테스트 항목: 말소기준등기 추출, 청구금액 분리, 선행 전입일 감지,
  잔존채권 포기 문구 감지, 등기 원문 없음 처리
- Nest 프로덕션 빌드 통과

## 남은 실측 검증

대표 운영 물건을 실제 AI에 전송해 결과를 생성하는 단계는 임차인 원문에
개인정보가 포함될 수 있어 별도 명시적 승인이 필요하다. 승인 후 5건만
실행해 예상 판정표와 실제 JSON 결과를 대조한다.

## 별도 보안 발견

운영 Railway 환경에 `JWT_SECRET`이 없어 개발용 기본값이 사용되고 있다.
전용 비밀키 설정 시 기존 로그인 세션이 만료되므로 별도 배포 시간에
변경해야 한다.

## 追記 — 운영 5건 실제 분석 결과

- 대표 운영 물건 5건을 승인 후 실제 분석하고 공용 결과로 저장.
- 5건 모두 청구금액을 인수금액으로 직접 합산하지 않았고 위험 상태로
  보수적으로 분류함.
- 줄바꿈된 등기에서 앞 행의 소유권이전을 말소기준권리로 잡는 오류 2건을
  발견해, 다음 행이 새 등기 행이면 결합하지 않도록 추출기 수정.
- `추가 확인 필요`라고 설명하면서 `assumption.status=none`을 반환하는
  모순 2건을 발견해, 구체적인 소멸·배당·채권 포기 근거가 없으면
  `unknown`으로 교정하도록 수정.
- RAG 5건은 모든 분석에서 검색됐으나 실제 적용 근거는 1건에서만
  기록됨. 근거가 비어 있으면 추가 자료 필요 사유로 표시하도록 보강.
- 지분매각 표본 재검증에서 예상 배당액 없이 임차보증금 일부를 인수
  가능 금액으로 제시한 사례를 발견. 예상 배당·미배당 잔액·잔존채권
  근거가 없는 추정 인수금액은 서버에서 `null`로 교정하도록 보강.

## 追記 — 관리자 AI 지식 정리 기능

- 관리자가 `권리분석` 분류를 선택하고 원본 메모를 `AI로 정리`하면
  일반 요약문이 아니라 아래 고정 구조로 생성하도록 전용 프롬프트 적용:
  적용 범위, 필수 입력, IF/THEN 판정 규칙, 금지 규칙, 추가 확인 자료,
  구조화 출력 예, 법적 근거 및 검토 기준.
- AI가 각 항목을 JSON 배열로 반환하고 서버가 최종 문서를 조립하므로
  모델의 문장 형식 차이와 관계없이 저장 형식을 일관되게 유지.
- 원문에 없는 법령·판례·금액을 만들지 않고, 법적 근거가 없으면
  `관리자 법령 검토 필요`로 표시하도록 제한.
- 다른 지식 분류는 기존 일반 정리 방식을 그대로 유지.

## 追記 — 숫자 등급을 RAG 적용 정책으로 전환

- 기존 DB 값은 마이그레이션 없이 그대로 사용:
  - `grade=1` → 항상 적용
  - `grade=2` → 관련 물건에 조건부 적용
  - `grade=3` → 참고 자료
- 권리분석 검색은 활성 `항상 적용` 문서를 모두 포함하고, 태그·제목·본문이
  물건과 일치하는 조건부 문서 최대 3개와 참고 문서 최대 1개를 추가.
- 분류 일치 점수와 숫자 등급 점수만으로 조건부 문서가 무조건 선택되지
  않도록 권리분석 검색에서는 실제 키워드 일치만 관련성 점수로 사용.
- 관리자 화면의 `1·2·3등급` 표기를 `항상 적용·조건부 적용·참고 자료`로
  변경.
- `npm run test:rag`로 항상 적용 전부 포함, 조건부 3개, 참고 1개 제한을
  회귀 검증.
- 운영 RAG 13건 본문을 점검하고 별도 작성 가이드
  (`docs/rights-rag-authoring-guide.md`)에 보완 우선순위 기록.

## 追記 — `조사된 임차내역 없음` 판정

- 법원 임차인·점유 현황에 `조사된 임차내역 없음`이 명시되고 별도 임차
  자료가 충돌하지 않으면 선순위 임차인·대항력을 `없음`으로 판정.
- 임차보증금 관련 낙찰자 인수권리와 금액은 `없음(0원)`으로 보정하고,
  임차인·전입·대항력 자료를 추가 요구하지 않음.
- 별도 전입일·보증금·임차인 정보가 함께 있으면 자료 충돌로 처리.
- 실제 점유·명도 상태와 임차인의 대항력·보증금 인수 여부는 분리해 판단.
- 같은 규칙을 활성 `권리분석` 조건부 RAG 문서로 운영 DB에 추가.

## 追記 — 말소기준권리 이후 전입 판정 검증

- `임차인 대항력 판단 및 보증금 인수 금액 판단` RAG가 선택돼도 AI가
  임차권등기·보증금 액수를 과대 해석해 날짜 선후관계와 반대 결론을 만드는
  사례를 확인.
- 원문에서 모든 전입일을 추출해 말소기준권리일과 직접 비교한 결과를 AI
  프롬프트의 서버 사전 점검 사실로 제공.
- 확인된 전입일이 모두 말소기준일보다 늦으면 AI가 작성한 설명을 유지하되,
  반대되는 대항력·인수보증금 판정은 결과 검증 단계에서 차단.
- 주택임대차 대항력은 인도와 주민등록을 마친 다음 날 0시부터 발생하므로,
  전입일과 말소기준권리일이 같으면 해당 임차인을 후순위·대항력 없음으로 판정.
