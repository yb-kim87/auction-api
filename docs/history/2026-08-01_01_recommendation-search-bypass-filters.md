# 추천 물건 검색: 필터 무시하고 전체 DB에서 검색

## 배경
사용자 요청(2026-08-01): "주소나 사건번호로 검색시에는 필터된 물건에서
보여주는게 아니라 DB있는 것에서 보여주면 될꺼같아" — 홈 화면(추천 물건
탭) 검색창이 예산/지역/물건종류 등 상세 필터를 통과한 후보군
(`affordable`) 안에서만 주소/사건번호를 매칭하고 있어, 필터 조건에
안 맞으면 실제로 존재하는 물건도 검색 결과에 안 뜨는 문제가 있었다.

## 변경
`recommendation-engine.service.ts`의 필터 체인에 `searchQuery` 존재 여부로
분기 추가:
- 예산 상한 필터(`requiredEquity <= investableWon`): 검색어가 있으면 건너뜀
- 목표수익 필터: 검색어가 있으면 건너뜀
- 지역/물건종류/유찰률/진행상태/전략라벨/면적 필터: 검색어가 있으면
  전부 건너뛰고 주소/사건번호 텍스트 매칭만 적용

즉 검색어를 입력하면 승인된 전체 물건 중 주소/사건번호가 일치하는
것만 반환하고, 다른 상세 필터는 전부 무시한다. 검색어가 없을 때의
기존 추천 필터링 동작은 그대로 유지.

## 검증
- `npx tsc --noEmit`, `npm run build` 통과.

## 追記 (2026-08-04) — 추천 기준 설명, 목록형 보기와 입찰일 상태

추천 물건이 사용자의 투자정보 조건을 통과한 결과임에도 카드에서 그 이유를
알 수 없어 단순 인기 물건처럼 보이던 문제를 개선했다.

- 사용자가 입력한 가용자금·주택 보유 상태 등 투자정보 기반으로
  `조건 여유`/`조건 경계`, 자금 사용률, 예상 필요자금, 가용자금 대비
  여유액과 적용 기준을 카드에 표시한다.
- `추천 이유`는 별도의 임의 점수가 아니라 실제 필터 통과 조건을 설명한다.
  입찰 전 확인이 필요한 임차인·대항력·미납 관리비 등의 주의사항도 함께
  노출한다.
- 카드형과 목록형 전환을 지원한다. 목록형은 썸네일과 사건·주소·입찰일을
  왼쪽에, 최소 투자금·예상 대출·최저가·감정가를 오른쪽에 정렬해 여러
  물건을 빠르게 비교할 수 있게 했다.
- 입찰일은 날짜만 표시하지 않고 `D-n · YYYY.MM.DD` 형태로 표시한다.
  임박 물건, 오늘 입찰, 종료, 기일 변경을 서로 다른 상태와 색으로 구분한다.

## 追記 (2026-08-05) — 리스트형 추천 물건 가독성 보완

리스트형 카드에서 사건번호·태그·면적/입찰기일·추천 근거와 가격 라벨이
10px 안팎으로 작아 장시간 비교할 때 읽기 어려웠다.

- 본문 보조 정보와 상태 태그는 모바일부터 약 10.5~12px, 데스크톱에서는
  약 11~13px로 한 단계 키웠다.
- 주소는 모바일 15px, 데스크톱 16px으로 키우되 기존 한 줄 말줄임을
  유지해 카드 폭과 높이가 과도하게 늘어나지 않게 했다.
- 데스크톱 우측 가격 영역은 라벨과 금액을 키우고 열 폭도 소폭 보정했다.
- 모바일에서는 우측 열이 아닌 하단 2열 가격 카드가 노출되므로, 해당
  카드의 라벨과 금액도 함께 키워 정보 위계가 일관되게 보이게 했다.

프론트 응답 확인 통과.

## 追記 (2026-08-05) — 추천 카드 투자정보 중복 제거

추천 카드의 투자정보 기준 영역 아래에 예상 필요자금·가용자금 여유·대출
기준을 다시 표시하고, 입찰 전 확인 태그도 중복 노출하고 있었다. 바로 아래
파란 투자금 요약 카드에 최소 투자금·예상 대출·추정 수익이 이미 있으므로
반복 정보는 제거했다.

- 투자정보 기준 영역에는 `조건 여유/경계`, `내 투자정보 기준`, 자금 사용률
  게이지만 남긴다.
- 금액과 대출 관련 세부 수치는 파란 요약 카드에서 한 번만 보여준다.
- 특수사항과 입찰 전 확인 신호는 상단 뱃지 및 카드 하단의 기존 정보로
  확인할 수 있어 중복 태그는 제외했다.
