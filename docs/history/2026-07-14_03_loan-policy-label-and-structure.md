# 대출 정책 라벨 표시 및 정책 구조 개선

날짜: 2026-07-14
관련 레포: auction, auction-api

## 배경

카드/상세페이지에 노출되는 대출 정책 라벨("규제지역 · 무주택(생애최초 포함)" 등)이
회원의 실제 생애최초 체크 여부와 다르게 표시되거나, 지역 접두어가 중복 표시되는 문제.
이후 규제지역도 비규제지역처럼 생애최초/무주택을 별도 정책으로 나눠 관리하고 싶다는 요청.

## 실행 프롬프트 (요약, 시간순)

```
그러면 저 부분 적용해서 보기 좋게 깔끔하게 나오게 해줘 (라벨 축약 로직 최초 도입)
그리고 첫번째 카드는 왜 생애최초포함이라고 나와? 이것도 체크안된건데 그냥 무주택이라고만 나와야지
2번째는 왜 무주택일반으로 나오는거지? 생애최초로 안나오고?
그러면 둘다 생애최초 체크안하면 규제/비규제 모두 무주택, 체크하면 모두 무주택생애최초로 표시하자
1번카드와 2번카드가 다르게 주택 보유정보가 나오면 안되고 같게 나와야지
여기 무주택(생애최초포함) 이부분도 물건리스트 카드처럼 그냥 무주택으로만 쓰자, 비규제도 마찬가지고
그리고 규제지역 라벨 가장 상단에 있으니까 규제지역/비규제지역도 쓸필요 없고
지금 대출 정책에서 규제지역도 비규제지역처럼 규제지역 생애최초/규제지역 무주택 이런식으로
나눠서 요율을 정하게 해줘
수정된게 이 화면 맞아?? 비규제지역처럼 나오게 해줘 / 무주택 일반이란 표현보단 그냥 무주택으로
순서도 비규제와 똑같이 규제지역 생애최초 다음에 규제지역 무주택 이런 순서로
```

## 문제와 해결 과정

1. **1차: 문자열 파싱 방식(실패)** — 정책 라벨 문자열에서 "(생애최초 포함)" 등을 정규식으로
   잘라내는 `shortLoanPolicyLabel`을 도입했으나, 규제지역 정책 자체가 생애최초 여부를
   구분하지 않는 구조라 회원의 실제 체크 여부와 무관하게 항상 "생애최초 포함"이 노출되는
   근본 불일치가 남음.
2. **2차: 회원 값 직접 참조** — `housingLoanLabel(loanPolicyLabel, firstTimeBuyer)`로 변경해
   정책 라벨 문자열이 아니라 회원의 `firstTimeBuyer` 값을 직접 보고 "무주택"/"무주택생애최초"를
   결정하도록 함. 다만 규제지역 정책 자체는 여전히 하나였으므로 "표시는 맞는데 실제 대출 계산은
   생애최초 여부와 무관"한 불일치가 남음.
3. **3차: 정책 구조 자체를 분리(근본 해결)** — 규제지역도 비규제지역과 동일하게
   `regulated_first_time`(생애최초)과 `regulated_no_house`(무주택)로 대출정책을 분리해,
   표시뿐 아니라 실제 대출한도 계산도 생애최초 여부에 따라 달라지도록 함.
4. **배포 후 라벨이 안 바뀌는 추가 버그** — `LoanPolicyService.onModuleInit`이 이미 DB에 있는
   정책 레코드는 label/sortOrder를 갱신하지 않고 건너뛰는 구조였음. 관리자가 조정한
   loanRatio/appraisalRatio는 보존하되 label/sortOrder/구분 플래그만 코드 기준으로
   동기화하도록 수정.

## 변경 내용

### 백엔드 (auction-api)
- `src/loan-policy/loan-policy.service.ts`
  - `DEFAULT_LOAN_POLICIES`: `regulated_no_house` 하나였던 것을 `regulated_first_time`
    (생애최초, sortOrder 0) + `regulated_no_house`(무주택, sortOrder 1)로 분리
  - 전체 라벨을 "OO 일반" → "OO"로 단순화(규제지역·무주택, 비규제지역·무주택)
  - `onModuleInit`: 기존 레코드도 label/sortOrder/regulatedArea/loanUnavailable/
    businessLoanOnly를 최신 정의로 동기화(비율 값은 보존)
- `src/recommendation/investment-math.util.ts`
  - `selectLoanPolicy`: 규제지역에서도 `firstTimeBuyer`로 `regulated_first_time` /
    `regulated_no_house` 분기하도록 수정

### 프론트엔드 (auction)
- `src/lib/loan-policy-label.ts` 신규(공용 유틸): `shortLoanPolicyLabel`, `housingLoanLabel`을
  `page.tsx`와 `AuctionDetailModal.tsx`가 함께 사용하도록 분리
- `src/lib/investment-criteria.ts`: 검색페이지 클라이언트 계산도 백엔드와 동일하게
  정책 분리 및 라벨 단순화 반영
- 카드/상세페이지 모두 "무주택"/"무주택생애최초"로 통일 표시, 지역 접두어 중복 제거

## 결과
- 관리자 화면 "대출 정책 관리"에 6개 정책이 규제지역(생애최초→무주택→1주택), 비규제지역
  (생애최초→무주택→1주택) 순서로 표시되고 각각 독립적으로 비율 조정 가능
- 표시 라벨과 실제 적용 대출 계산이 완전히 일치

## 추가: 정책 저장 방식을 통합 저장 버튼으로 변경 (2026-07-14 追記)

### 배경
정책이 6개(추후 더 늘 수 있음)로 늘어나면서, 정책마다 개별 "저장" 버튼을 눌러야 하는 방식이
여러 정책을 한꺼번에 조정할 때 번거롭다는 피드백. "저장 버튼 1개로 통합해서 여러 개
바꾸고 한꺼번에 저장하고 싶다"는 요청.

### 실행 프롬프트 (요약)
```
여기서 저장버튼 1개만 있으면 될꺼같아 여러개 바꾸고 한꺼번에 저장할 수 있게
```
(진행 중 사용자가 로컬 화면을 다시 확인하고 "아 아니다"라며 1차 취소 → 이전 커밋으로 되돌림.
이후 화면을 다시 확인한 뒤 "아 아니다 다시 버튼 하나로 만들어줘"로 재요청해 최종 진행.)

### 변경 내용 (auction)
- `src/app/admin/LoanPolicyTab.tsx`
  - `originalPolicies`(로드 시점 원본 스냅샷)를 별도로 보관해 각 정책의 변경 여부(`isDirty`)를
    판정
  - 정책별 "저장" 버튼과 그 컬럼을 제거하고, 테이블 하단에 "변경사항 저장" 버튼 하나만 배치
  - 값이 바뀐 행은 옅은 배경색으로 강조 표시, 버튼 옆에 "변경된 정책 N개" 카운트 표시
  - 저장 시 변경된 정책들만 골라 `Promise.all`로 병렬 PATCH 요청, 성공한 정책들의 원본
    스냅샷을 갱신
  - 백엔드 API(`updateLoanPolicy`, 단건 PATCH)는 변경하지 않음 — 프론트에서 변경분만 추려
    여러 번 호출하는 방식으로 처리(별도의 벌크 API는 만들지 않음)

### 결과
- 여러 정책의 감정가/낙찰가 비율을 동시에 수정한 뒤 버튼 한 번으로 일괄 저장 가능
- 변경하지 않은 정책은 저장 요청에 포함되지 않아 불필요한 API 호출 없음
