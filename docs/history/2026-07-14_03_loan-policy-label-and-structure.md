# 대출 정책 라벨 표시 및 정책 구조 개선

날짜: 2026-07-14
관련 레포: auction, auction-api

## 배경

카드/상세페이지에 노출되는 대출 정책 라벨("규제지역 · 무주택(생애최초 포함)" 등)이
회원의 실제 생애최초 체크 여부와 다르게 표시되거나, 지역 접두어가 중복 표시되는 문제.
이후 규제지역도 비규제지역처럼 생애최초/무주택을 별도 정책으로 나눠 관리하고 싶다는 요청.

## 실행 프롬프트 (요약, 시간순)

```
그러면 저 부분 적용해서 보기 좋게 깔끔하게 나오게 해줘 (라벨 축약 로직 최초 도입)
그리고 첫번째 카드는 왜 생애최초포함이라고 나와? 이것도 체크안된건데 그냥 무주택이라고만 나와야지
2번째는 왜 무주택일반으로 나오는거지? 생애최초로 안나오고?
그러면 둘다 생애최초 체크안하면 규제/비규제 모두 무주택, 체크하면 모두 무주택생애최초로 표시하자
1번카드와 2번카드가 다르게 주택 보유정보가 나오면 안되고 같게 나와야지
여기 무주택(생애최초포함) 이부분도 물건리스트 카드처럼 그냥 무주택으로만 쓰자, 비규제도 마찬가지고
그리고 규제지역 라벨 가장 상단에 있으니까 규제지역/비규제지역도 쓸필요 없고
지금 대출 정책에서 규제지역도 비규제지역처럼 규제지역 생애최초/규제지역 무주택 이런식으로
나눠서 요율을 정하게 해줘
수정된게 이 화면 맞아?? 비규제지역처럼 나오게 해줘 / 무주택 일반이란 표현보단 그냥 무주택으로
순서도 비규제와 똑같이 규제지역 생애최초 다음에 규제지역 무주택 이런 순서로
```

## 문제와 해결 과정

1. **1차: 문자열 파싱 방식(실패)** — 정책 라벨 문자열에서 "(생애최초 포함)" 등을 정규식으로
   잘라내는 `shortLoanPolicyLabel`을 도입했으나, 규제지역 정책 자체가 생애최초 여부를
   구분하지 않는 구조라 회원의 실제 체크 여부와 무관하게 항상 "생애최초 포함"이 노출되는
   근본 불일치가 남음.
2. **2차: 회원 값 직접 참조** — `housingLoanLabel(loanPolicyLabel, firstTimeBuyer)`로 변경해
   정책 라벨 문자열이 아니라 회원의 `firstTimeBuyer` 값을 직접 보고 "무주택"/"무주택생애최초"를
   결정하도록 함. 다만 규제지역 정책 자체는 여전히 하나였으므로 "표시는 맞는데 실제 대출 계산은
   생애최초 여부와 무관"한 불일치가 남음.
3. **3차: 정책 구조 자체를 분리(근본 해결)** — 규제지역도 비규제지역과 동일하게
   `regulated_first_time`(생애최초)과 `regulated_no_house`(무주택)로 대출정책을 분리해,
   표시뿐 아니라 실제 대출한도 계산도 생애최초 여부에 따라 달라지도록 함.
4. **배포 후 라벨이 안 바뀌는 추가 버그** — `LoanPolicyService.onModuleInit`이 이미 DB에 있는
   정책 레코드는 label/sortOrder를 갱신하지 않고 건너뛰는 구조였음. 관리자가 조정한
   loanRatio/appraisalRatio는 보존하되 label/sortOrder/구분 플래그만 코드 기준으로
   동기화하도록 수정.

## 追記 (2026-08-05) — 방공제 계산 방식 정정(최종 min 이후 차감 → 적용 대상 기준금액 차감)

사용자 피드백: "차감되는 로직에 대해서 수정할께 있어. 감정가 60% 낙찰가
80% 중에 낮은게 기본로직인데, 방공제 적용항목이 감정가면 감정가 60% -
방빼기 = 나온 금액과 낙찰가 80% 중 낮은 금액이 최종 대출 금액이 나오도록
해줘. 만약에 낙찰가로 적용하면 감정가 60% 낙찰가 80% - 방공제 두 금액 중
낮은거. 둘다면 둘다 방공제를 뺀 결과 중에 낮은 금액이 대출 금액으로
나오도록." 이어서 "방공제가 체크박스가 아니라 드롭박스로 감정가/낙찰가/
둘다/미적용 이렇게 선택해서 적용되게 해줘, 기본은 미적용."

바로 위 항목(같은 날 최초 구현)에서는 방공제 금액을 `existingLoanWon`
(기존대출)에 합산해 **min(감정가 기준, 낙찰가 기준) 결과가 나온 뒤에**
일괄 차감했는데, 이는 사용자가 원한 계산과 다르다(예: 감정가 기준에만
방공제가 적용돼야 하는데 낙찰가 기준이 이미 더 낮아서 min으로 뽑혔다면
방공제가 반영되면 안 됨). 아래처럼 정정:

- `loan_policies.roomDeductionEnabled`(boolean) →
  `roomDeductionTarget`(text: `"none"|"appraisal"|"bid"|"both"`, 기본
  `"none"`)로 마이그레이션(`1784279000000-ChangeLoanPolicyRoomDeductionToTarget`,
  기존 `true`였던 정책은 `"both"`로 이관).
- `investment-math.util.ts`의 `maxLoanAmount`/`requiredEquityForItem`,
  `profit-calculator.util.ts`(백엔드)와 `profit-calculator.ts`(프론트)의
  `calculateProfit`/`estimateDefaultProfit`에 각각
  `roomDeductionWon`/`roomDeductionTarget` 파라미터 추가 — **min을 구하기
  전에** 지정된 기준(`appraisal`이면 감정가×비율, `bid`면 낙찰가×비율,
  `both`면 둘 다)에서 방공제를 먼저 뺀 뒤 그 값들 중 최저가를 최종
  대출한도로 삼는다. 기존대출(`existingLoanWon`) 차감은 지금처럼 최종
  min 결과에서 그대로 이루어진다(방공제와 계산 시점이 다름).
- `LoanPolicyTab.tsx`: 체크박스 → `<select>`(미적용/감정가/낙찰가/둘다)로
  변경.
- `RecommendCard.tsx`: `LoanInfo`에 `roomDeductionWon`/`roomDeductionTarget`
  둘 다 추가해 "추정 수익" 재계산 시 `existingLoanWon`에 합산하던 임시
  방식을 걷어내고 정식 파라미터로 전달.
- `page.tsx`: `AuctionDetailModal`에 넘기던 `existingLoanWon`에 방공제를
  합산했던 임시 코드를 되돌림(방공제 표시 라벨이 "기존대출"로 잘못
  뜨는 문제도 함께 제거).

- 서버 정책 초기화 시 기존 통합 정책의 대출 비율·대출 불가 여부·방공제 적용 기준을 두 새 정책에 복사한다. 따라서 운영에서 관리자가 설정한 값은 배포 후에도 유지된다.
- 기존 통합 정책 행은 호환성 보존용으로 DB에 남기되, 관리자 조회 API에서는 제외해 중복 표시하지 않는다.
- 추천 엔진과 프론트엔드 목록 계산 모두 물건 용도·소재지·공시가격으로 같은 우선순위를 적용한다.

### 결과

- 오피스텔은 공시가격이 비어 있거나 2억 원을 초과해도 오피스텔 정책이 적용된다.
- 지방 아파트만 공시가격 2억 원 이하일 때 저가 아파트 정책이 적용된다.
- 관리자 화면에서 두 정책을 독립적으로 수정·저장할 수 있다.
