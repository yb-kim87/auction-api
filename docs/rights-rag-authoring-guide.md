# 권리분석 RAG 작성 가이드

## 기본 원칙

권리분석 지식은 설명문보다 **판정 규칙**으로 작성한다. 한 지식에는 한
주제만 넣고, 물건 원문에 없는 사실을 추론하도록 유도하지 않는다.

권장 구성:

```text
제목: [주택임대차] 대항력 판단
분류: 권리분석
등급: 1
태그: 주택임대차,대항력,점유,전입일,말소기준권리

[적용 범위]
주거용 건물의 임차인 대항력 1차 판단

[필수 입력]
- 실제 점유 여부와 점유 시작일
- 주민등록 전입일
- 말소기준권리 종류와 접수일

[판정 규칙]
- IF 점유 또는 전입 중 하나라도 미확인
  THEN opposability=unknown
- IF 대항요건 발생 시점이 말소기준권리보다 빠름
  THEN opposability=possible
- 확정일자는 대항력 요건이 아니라 우선변제권 판단 자료로 분리

[금지 규칙]
- 전입일만으로 대항력을 확정하지 않는다.
- 확정일자가 없다는 이유만으로 대항력이 없다고 판단하지 않는다.
- 임차보증금 총액을 인수금액으로 사용하지 않는다.

[추가 확인 자료]
현황조사서, 전입세대확인서, 매각물건명세서, 배당요구 및 배당표

[출력 예]
priorityStatus=possible
opposability=unknown
assumption.status=unknown
missingEvidence=["실제 점유 시작일", "예상 배당액"]

[법적 근거]
주택임대차보호법 제3조, 제3조의2
검토 기준일: YYYY-MM-DD
```

## 적용 방식과 검색

- `항상 적용`(기존 값 1): 모든 권리분석에 넣을 핵심 법칙. 말소기준권리, 주택·상가 대항력,
  선순위 임차인, 인수금액 산정 원칙.
- `조건부 적용`(기존 값 2): 특정 상황의 예외. HUG·LH 등 보증기관 채권 승계 및 포기,
  임차권등기, 유치권, 지분매각.
- `참고 자료`(기존 값 3): 사례·경험·체크리스트. 단독 결론의 근거로 사용하지 않는다.

태그에는 상위 개념과 원문에 실제 등장하는 표현을 함께 넣는다. 예:
`보증기관,HUG,주택도시보증공사,임차권등기,잔존채권포기`.

## 입력 시 피해야 할 방식

- 여러 법적 주제를 한 문서에 섞기
- “가능성이 높다”처럼 조건과 근거가 없는 결론
- 대항력과 우선변제권을 같은 요건으로 설명
- 청구금액·채권최고액·보증금 총액을 인수금액으로 단정
- 사례 한 건의 결과를 일반 법칙으로 등록
- 법령 검토일과 적용 범위가 없는 오래된 문서
- `초안` 상태의 문서를 활성화한 채 운영 분석에 사용

## 운영 점검 체크리스트

1. 제목과 태그만 보고 적용 대상을 구분할 수 있는가?
2. 필수 입력이 없을 때 `unknown`으로 끝내는 규칙이 있는가?
3. 대항력·우선변제권·배당·인수금액을 각각 분리했는가?
4. 예외와 금지 규칙이 있는가?
5. 구조화 결과 필드와 예상값을 예시로 제공했는가?
6. 법적 근거와 최종 검토일이 있는가?
7. 동일하거나 충돌하는 지식이 중복 등록되지 않았는가?

## 현재 운영 지식 보완 우선순위

1. `무상거주사실확인서와 임차인의 대항력`의 “대항력은 전입신고와
   확정일자가 필요” 문구 수정. 확정일자는 우선변제권 자료로 분리한다.
2. `주택임대차 vs 상가임대차...`의 “상가 임차인은 우선변제권과
   최우선변제권이 없다” 문구 수정. 상가건물 임대차보호법 제5조와
   제14조의 요건을 기준으로 다시 작성한다.
3. `미상임차인 가이드`와 `대항력 있는 임차인 확인 가이드`는 내용이
   동일하므로 하나로 통합한다.
4. 활성 상태인 `[초안]` 문서는 검토 완료 전 비활성화하고, 완료 후
   `[초안]`을 제거하여 1등급 핵심 규칙으로 운영한다.
5. `유치권 물건 대출 가능성 분석`은 권리 성립 판단과 대출 가능성
   내용을 분리한다.
6. `소유자 사망 아파트 경매 시 고려사항`은 권리분석 핵심 RAG가 아니라
   사례·투자 체크리스트 분류로 이동한다.
7. HUG·LH·SGI의 보증금반환채권 승계, 잔존채권 포기 확약서,
   임차권등기 말소 동의를 별도 2등급 지식으로 추가한다.
